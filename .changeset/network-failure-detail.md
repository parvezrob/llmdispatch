'llmdispatch': patch
---

A built-in adapter's network failure now says what kind of failure it was. The `ProviderError('transient')` it throws when a request or its response body fails used to read `network failure` and nothing more; it now adds the error `code` of the thrown error or its `cause` when there is one, as in `network failure (ECONNRESET)`, `network failure (ENOTFOUND)` or `network failure (UND_ERR_CONNECT_TIMEOUT)`, and `network failure (redirect refused)` when a provider answered with a redirect, which the adapters never follow. A code is kept only when it is shaped like the ones Node, undici and OpenSSL set: errno-style codes such as `EAI_AGAIN`, Node's `ERR_*`, undici's `UND_ERR_*`, and OpenSSL's certificate codes such as `DEPTH_ZERO_SELF_SIGNED_CERT` or `CERT_HAS_EXPIRED` (spec §5c lists the pattern and the certificate codes). The shape is the only check, so a `fetch` your application installs could still put short upper-case text in `code`; such a wrapper must not put a secret there. The error's message, any URL it names and anything else on it are never kept, since a URL can carry a key. The classification, the fallback and the attempt record are unchanged: the detail is on the `ProviderError` itself, so code that wraps a provider and catches what `complete()` throws can log it.
